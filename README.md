# Media Fetch Bot — بوت تيليجرام لتنزيل الوسائط

بوت Python لتيليجرام يساعد المستخدم على تنزيل وسائط عامة من المواقع التي يتعرف عليها `yt-dlp`، مع اختيار جودة الفيديو أو استخراج الصوت بصيغة MP3. المشروع مجهز للتشغيل محليًا أو داخل Docker أو Railway، ويتضمن إعدادات آمنة افتراضيًا، قاعدة SQLite، اختبارات، وتدفق GitHub Actions.

> استخدمه فقط مع المحتوى الذي تملكه أو لديك إذن صريح بتنزيله. لا يتجاوز المشروع DRM أو جدران الدفع أو تسجيل الدخول، ولا يدعم الروابط الخاصة.

## ما الذي يتضمنه؟

- واجهة عربية وأزرار تفاعلية لاختيار جودة متاحة من المصدر، مع تنزيل MP3.
- تقسيم الفيديو والصوت الكبير تلقائيًا إلى ملفات مستقلة مرقّمة، مع التحقق من أن حجم كل جزء ضمن الحد.
- دعم مواقع كثيرة عبر محركات `yt-dlp`، لكن التغطية تتغير حسب الموقع والرابط والمنطقة وسياسات المنصة؛ لا يوجد ضمان أن «كل منصة» ستعمل دائمًا.
- حد مدة وحجم، عدد محدود من التنزيلات المتزامنة، مهلة بين طلبات المستخدم، ورسائل خطأ مفهومة.
- تحقق أولي من الروابط العامة لمنع العناوين المحلية، ورفض عناوين الدخول المضمنة في الرابط.
- حذف الملفات المؤقتة بعد الإرسال، وعدم تخزين روابط التنزيل في قاعدة البيانات.
- إحصاءات استخدام مقتصرة على مالك البوت، وملف SQLite قابل للاستمرار عبر Railway Volume.
- Dockerfile و`railway.json` و`.env.example` واختبارات وCI.

## المتطلبات

- Python 3.11 أو أحدث، وFFmpeg.
- توكن Bot من [@BotFather](https://t.me/BotFather).
- اتصال إنترنت. بعض المواقع تتغير أو تحجب طلبات الخوادم، وقد لا تكون بعض الصيغ متاحة.

## تشغيل محلي

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -e .
cp .env.example .env
```

عدّل `.env` وأضف `BOT_TOKEN`. ثبّت FFmpeg من مدير الحزم الخاص بنظامك، ثم:

```bash
set -a && source .env && set +a
python -m mediabot.main
```

> لا ترفع ملف `.env` أو توكن البوت إلى GitHub. إذا ظهر التوكن في سجل أو مستودع، ألغِه فورًا من BotFather وأنشئ توكنًا جديدًا.

## النشر على Railway

1. ارفع محتويات هذا المشروع إلى مستودع GitHub خاص أو عام.
2. في Railway اختر **New Project → Deploy from GitHub Repo** وحدد المستودع. سيُبنى المشروع باستخدام `Dockerfile` الموجود في الجذر.
3. أضف المتغير `BOT_TOKEN` من صفحة **Variables**. أضف `OWNER_IDS` كرقم حساب تيليجرام الخاص بك، مثل `123456789`، لتفعيل `/stats`.
4. أضف Volume للخدمة واجعل نقطة الربط `/data` حتى تبقى قاعدة SQLite موجودة بعد إعادة النشر. ملفات التنزيل نفسها مؤقتة في `/tmp` وتُحذف بعد الإرسال.
5. انشر الخدمة وتحقق من السجل حتى تظهر رسالة بدء الاستطلاع. لا تحتاج الخدمة إلى منفذ HTTP لأن البوت يستخدم long polling؛ شغّل نسخة واحدة من الخدمة ولا تضاعف replicas للبوت نفسه.

`railway.json` يحدد Dockerfile وسياسة إعادة التشغيل. قد تختلف أسماء الأزرار في لوحة Railway بمرور الوقت؛ راجع [دليل Dockerfiles](https://docs.railway.com/guides/dockerfiles) و[دليل الخدمات والنشر من GitHub](https://docs.railway.com/guides/services). التخزين خارج Volume مؤقت، لذا لا تحفظ قاعدة البيانات خارجه.

## إعدادات البيئة

| المتغير | مطلوب | الافتراضي | الاستخدام |
|---|---:|---:|---|
| `BOT_TOKEN` | نعم | — | توكن BotFather. |
| `OWNER_IDS` | لا | فارغ | أرقام حسابات المالك مفصولة بفواصل؛ تظهر لها `/stats`. |
| `MAX_FILE_MB` | لا | `48` | أقصى حجم لكل ملف/جزء يُرسل. القيمة مقيدة إلى 50 كحد أقصى. |
| `MAX_SOURCE_FILE_MB` | لا | `256` | أقصى حجم للمصدر الذي يُنزّل قبل التقسيم؛ اضبطه حسب مساحة التخزين المتاحة. |
| `MAX_DURATION_SECONDS` | لا | `3600` | أقصى مدة للوسائط بالثواني. |
| `MAX_CONCURRENT_DOWNLOADS` | لا | `1` | أقصى عدد عمليات تنزيل متزامنة. |
| `USER_COOLDOWN_SECONDS` | لا | `8` | أقل مدة بين بدء طلبات المستخدم. |
| `DATA_DIR` | لا | `/data` | مجلد قاعدة SQLite؛ على جهازك يمكن ضبطه على `./data`. |
| `TEMP_DIR` | لا | `/tmp/media-fetch-bot` | مجلد ملفات العمل المؤقتة. |
| `LOG_LEVEL` | لا | `INFO` | مستوى السجل: `DEBUG`, `INFO`, `WARNING`, `ERROR`. |

يمكن ضبط `MAX_FILE_MB` إلى قيمة بين 1 و50. تذكر وثائق Bot API الحالية سقفًا قدره 50 MB للملفات التي يرفعها البوت؛ لذلك القيمة الافتراضية 48 MB تترك هامشًا. تشغيل خادم Telegram Bot API محلي يغير بعض الحدود، لكنه خارج نطاق هذا المشروع.

### الملفات الأكبر من حد الإرسال

إذا تجاوز الفيديو أو الصوت `MAX_FILE_MB`، يقسمه FFmpeg إلى أجزاء مستقلة ويرسلها في رسائل منفصلة بأسماء مثل `part_01` و`part_02`. كل جزء يمكن تشغيله وحده؛ لن يظهر كفيديو واحد متصل داخل تيليجرام. يبدأ التقسيم بنسخ المسارات الصوتية والمرئية دون إعادة ترميز للمحافظة على الجودة. إذا لم تسمح نقاط المفتاح أو الحاوية بتقسيم صالح، يعيد FFmpeg ترميز الفيديو إلى MP4 متوافق وقد تنخفض الجودة قليلًا.

يُنزّل البوت المصدر كاملًا مؤقتًا قبل التقسيم، لذلك الحد الافتراضي للمصدر `256 MB` والمدة ساعة واحدة. احتفظ بحد المصدر وعدد عمليات متزامنة منخفضين على خطة استضافة ذات مساحة مؤقتة محدودة. إذا تجاوز المصدر الحد، يطلب البوت اختيار جودة أقل؛ لا يرفع الحد تلقائيًا.

## أوامر البوت

- `/start` أو `/help` — المساعدة.
- أرسل رابطًا عامًا — فحص ثم خيارات الجودة والصوت.
- `/audio URL` — تنزيل الصوت بصيغة MP3.
- `/queue` — حالة توفر التنزيلات المتزامنة.
- `/cancel` — حذف خيارات الجودة المعلّقة الخاصة بك.
- `/about` — شرح الخصوصية والحدود.
- `/stats` — إحصاءات للمالك المحدد في `OWNER_IDS` فقط.

## التشغيل باستخدام Docker

```bash
cp .env.example .env
# أضف BOT_TOKEN إلى .env
mkdir -p data
docker compose up --build -d
docker compose logs -f bot
```

أوقف الخدمة باستخدام `docker compose down`. يحتوي Docker على Python وFFmpeg وDeno. الـ Volume المحلي يحفظ SQLite في `./data`.

## الخصوصية والأمان

يخزن التطبيق أرقام المستخدمين وأوقات النشاط وعدد التنزيلات لأغراض الإحصاءات فقط. لا يُخزن الرابط أو ملف الوسائط بعد الإرسال. قد تتضمن سجلات `yt-dlp` تفاصيل تقنية عند ضبط `LOG_LEVEL=DEBUG`؛ لا تنشر سجلات تحتوي روابط خاصة. التحقق من DNS والعناوين المحلية إجراء دفاعي مبدئي وليس بديلًا عن تشغيل الخدمة في بيئة معزولة وتحديث `yt-dlp` بانتظام.

لا تضع Cookies أو بيانات اعتماد للمواقع في البوت. لا تحمّل مواد غير قانونية أو محمية. التزم بقوانين بلدك وشروط استخدام المصدر. راجع `docs/benchmark.md` لمقارنة المشاريع المرجعية ومصادر الميزات والحدود.
